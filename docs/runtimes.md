# Runtime Backends

Generated by `scripts/validate_runtimes.py` on the benchmark host. Each available backend runs the trained detector on a real test image; outputs are compared with PyTorch FP32 on CPU using the precision tier's gate from `configs/yolo/<precision>.yaml`. `GATE FAIL` means the backend runs correctly but its output deviates more than the precision tier allows; `ERROR` means it could not run.

## Implementation summary

| Backend | Module | Execution details |
| --- | --- | --- |
| PyTorch eager | `src/runtimes/pytorch_runtime.py` | `torch.inference_mode()`, CPU threads pinned to the visible core count; CUDA path is asynchronous (no per-call sync) |
| ONNX Runtime CPU | `src/runtimes/ort_cpu_runtime.py` | `ORT_ENABLE_ALL` graph optimizations, sequential execution, intra-op threads = visible cores, inter-op = 1 |
| ONNX Runtime CUDA | `src/runtimes/ort_cuda_runtime.py` | IOBinding with pre-allocated device outputs on the PyTorch stream; provider audited at load |
| TensorRT | `src/runtimes/tensorrt_runtime.py` | Deserialized engine, static-shape device buffers, input copy + `execute_async_v3` ordered on a dedicated stream |

`FallbackAuditor` (`src/runtimes/fallback_audit.py`) raises if a requested ORT provider is not the session's primary provider, or if a CUDA PyTorch runtime holds parameters off-device. It does not inspect per-node placement inside a session.
